# Angular 21 upgrade verification (2026-11-13)

## Compatibility checked before migration

Registry inspection selected the newest stable 21.x versions available on 2026-11-13: framework 21.2.26, CLI/build/SSR 21.2.30, Material/CDK 21.2.14, NgRx Signals 21.1.1 and Toolkit 21.0.1. Different patch numbers belong to independently released package groups.

Node **24.22.1**, npm **11.21.1**, TypeScript **5.9.2**, RxJS **7.8.0**, Zone.js **0.15.0** are retained. Angular 21 supports Node ^20.19.0 / ^22.12.0 / ^24.0.0, TypeScript >=5.9 <6 and RxJS ^6.5.3 / ^7.4.0. Target package engines and peers were checked as well; the installed compiler/build require TypeScript >=5.9 <6. CI uses Node 20, whose current patch meets the 20.19 floor.

Context7 was used with the official Angular 21 documentation collection and the versioned Angular source collection. References: [Angular 21 compatibility](https://v21.angular.dev/reference/versions), [Angular 21 ng update](https://v21.angular.dev/cli/update), [Angular 20 → 21 guide](https://v21.angular.dev/update-guide?v=20.0-21.0&l=3). The documentation snapshot's compatibility table labels 21.0.x; exact 21.2.26/21.2.30 requirements were additionally verified against npm package metadata and installed manifests.

All directly installed Angular-related packages and their complete peers are recorded below. Optional absent integrations are not installed merely to satisfy this audit. All present peers satisfy their ranges (0 errors). NgRx Signals and Toolkit 20 require Angular 20, so both must move to 21. Material/CDK 20 allow Angular 21, but move together to the current matching 21 pair and execute their official migrations. TanStack's existing Angular >=16 peers already permit 21; its package remains unchanged. Build/SSR/framework move in their official package groups.

## Official migration execution

Initial command (no force, no legacy-peer-deps):

```powershell
node node_modules/@angular/cli/bin/ng.js update @angular/core@21 @angular/cli@21 @angular/material@21 @ngrx/signals@21 @angular-architects/ngrx-toolkit@21 --allow-dirty
```

The CLI selected all target package groups without a peer rejection. The first npm installation failed with ENOENT for a missing npm cache content file. A subsequent plain npm install completed with the same target manifest. Its transient peer warning referenced the partially installed old common/core 20.2.1 pair; final full npm ls reports no dependency problems, and npm install --package-lock-only --strict-peer-deps --ignore-scripts --no-audit --no-fund succeeds. No peer bypass was used. Windows reported cleanup warnings for old loaded native-module files; installation and builds succeeded.

Because installation stopped before migrations, every applicable official migration collection was explicitly executed with ng update --migrate-only --allow-dirty and these bounds:

SSR, build and Toolkit do not declare their own ng-update migration collections in the target manifests. CLI migration runs disabled only its redundant online version check after the exact installed CLI target had already been verified. Optional migrations were not selected. Forms remain typed Reactive Forms; no signal forms, zoneless conversion, test-runner migration or unrelated refactor was performed. Existing explicit zone providers, polyfills, source and tests are retained. Angular animations remains installed despite its deprecation; replacing it is outside this upgrade.

The focused serial WebKit rerun passed both, and the subsequent complete serial WebKit run passed all 137 cases without retries. Do not interpret the initial failures as verified Angular regressions or as fixed: no application/test behavior was changed, and the Firefox cases were not investigated further after the user's scope change.

Port 4200 was occupied by an existing development server running code loaded before dependency replacement. Tests therefore used a separate Angular 21 server on port 4201 and a temporary ignored Playwright configuration. The shared fixture hardcodes port 4200 and cannot be overridden by Playwright configuration alone, so only its URL was temporarily changed during execution and restored byte-for-byte afterward. The first attempt that still reached the old server was aborted and is excluded from the completed run counts. The application's source, committed tests and Playwright configuration remain unchanged. Restart any previously running `npm start` process after updating dependencies.
